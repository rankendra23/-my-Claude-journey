8 · Agent responsibilities

Planner diagnoses language, root cause and fix strategy once. Executor writes the first fix. Evaluator scores correctness + regression safety (0–100, JSON) and lists remaining bugs. Critic adversarially hunts regressions, edge cases and unsafe code. Stop check (code, every round) fires on: (1) plateau — gain <2 pts two rounds running, (2) consensus — Evaluator and Critic both report 0 bugs, (3) hard cap of 10 rounds (fallback). Improver receives the previous draft + that round's evaluation + critique + memory and rewrites the code. Memory Manager compresses lessons so context threads forward. Final Reviewer writes the verdict after a stop fires. Safety Monitor is folded into the Critic's safety_flags.

9 · Architecture, extensions & next prompts

Architecture: a runtime while(true) loop; each pass makes live Evaluator → Critic → Memory calls, then the stop check, then (if continuing) an Improver call. Round count is whatever the stop check produces. Failed calls retry with backoff; malformed JSON is re-requested.

Extensions: run JS fixes in a sandboxed iframe for real test execution · user-supplied test cases as the rubric · diff view between rounds · Safety Monitor as a separate agent · parallel Critics with voting.

Further prompts: “Add a test-generator agent whose tests the Evaluator must run” · “Add a human-approval gate before the Final Reviewer” · “Make agents specialize by language and route automatically.”
