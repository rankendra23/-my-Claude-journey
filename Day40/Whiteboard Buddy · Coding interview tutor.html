How this was built

The system prompt

The tutor is told to return one strict JSON object, so the interface can draw a dial, complexity cards and flagged code lines instead of a wall of chat text. The prompt pins down the role (a friendly senior engineer coaching interview candidates), a scoring rubric, a spoiler rule (hints before solutions), and edge cases: off-topic input, missing code, and text inside the user’s paste that tries to give the tutor new orders.


  
Why the interface fits

  
  • The score dial answers “how did I do?” at a glance, and animates once per result.
    • 
  
  • Code is shown with line numbers and amber flags, the way a reviewer would mark a whiteboard.
    • 
  
  • Your complexity sits next to the optimal one, because interviewers ask for exactly that comparison.
    • 
  
  • Hints open one at a time and the solution stays hidden until you ask, so you attempt first.

  
How to extend it

  
  • Tools: pass a test-runner function in the sample call’s tools option so the tutor can execute your code.
    • 
  
  • Memory: save weak topics and scores per person, then pick the next challenge from them.
    • 
  
  • Multi-step flows: add a timed mock round: challenge, 20-minute timer, review, follow-up question.
